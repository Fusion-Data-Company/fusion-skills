## Buyer lifecycle

POST /api/account action cancel_subscription verifies the signed-in buyer against Stripe subscription metadata, sets cancel_at_period_end and reconciles saved access while sharing the billing webhook lock. It never cancels immediately or issues refunds. Repeated requests have a stable provider idempotency key. Billing webhook persists cancellation state. No provider calls were made during this build.

POST action recover_keys reveals only the authenticated buyer tenant's current incoming and CRM callback signing keys, with no-store response and a secret-free audit event. POST rotate_incoming_key with confirm:true replaces only the incoming key and logs the action. The old key stops authenticating new requests immediately; accepted jobs remain saved. Recover keys can recover a rotation whose HTTP response was lost. Callback key stays stable for pending/in-flight delivery. UI offers explicit confirmation for cancellation/rotation, hides secrets on sign-out, and a Hide keys control. Final authenticated lifecycle was not exercised against Clerk, Stripe or a database.
